# Prompt Engineering & Structured Output

### 1. Problem statement

Enterprise applications requiring structured data (such as JSON) from LLMs frequently fail due to malformed syntax (missing brackets, trailing commas), unexpected output wrapping, missing required fields, and hallucinated data when source inputs are incomplete. Relying on plain-text prompts to generate structured JSON offers no syntax guarantees and increases failure rates in automated pipelines. Furthermore, high-volume batch processing using real-time API calls leads to prohibitive token costs and rate-limit bottlenecks.

### 2. Summary

The [Prompt Engineering & Structured Output](https://pods.vizuara.ai/courses/claude-certified-architect/prompt-engineering-structured-output) module covers key techniques for guaranteed JSON extraction, prompt optimization, schema safety, validation-retry loops, and cost reduction strategies for the Claude Certified Architect Foundations exam:

* **Structured Output Hierarchy**: `tool_use` with a JSON schema completely eliminates JSON syntax errors (brackets, trailing commas, quotes) compared to prompt-based JSON requests.
* **`tool_choice` Selection Modes**:
    * `auto`: Allows Claude to return either plain text or a tool call (no structural guarantee).
    * `any`: Forces Claude to invoke a tool, but lets the model select which tool from the schema list.
    * `{"type": "tool", "name": "extract_data"}`: Forces Claude to execute a specific tool on the turn, ensuring reliable single-step extraction.


* **Schema Design & Fabrication Prevention**: `tool_use` eliminates *syntax* errors but does NOT eliminate *semantic* errors (e.g., incorrect sums, wrong field assignments, or fabricated data). To prevent model fabrication when information is absent from source documents, mark optional fields as nullable (`"type": ["string", "null"]`) or make fields non-required.
* **Validation-Retry Loops**: When validation fails (e.g., line-item totals do not sum correctly), developers must append the failed assistant turn alongside specific diagnostic feedback (`"The total does not match the line item sum of $150"`) to allow Claude to correct its output on the subsequent turn.
* **Batch API & Cost Optimization Stack**: For non-latency-sensitive workloads (evaluations, backfills), the Batch API offers a **50% price reduction** with a 24-hour completion window. Stacking Prompt Caching with the Batch API compounds savings by applying the 50% batch discount on top of cached token read discounts.

## Code Snippets & Explanations

#### 1. Guaranteed Structured Output via Forced Tool Call & Nullable Schema

```python
import anthropic

client = anthropic.Anthropic()

# Tool schema with nullable fields to prevent hallucination of missing values
extraction_tool = {
    "name": "submit_invoice_data",
    "description": "Extract structured invoice data. Set missing fields to null.",
    "input_schema": {
        "type": "object",
        "properties": {
            "invoice_id": {"type": "string"},
            "vendor_name": {"type": "string"},
            "purchase_order_number": {"type": ["string", "null"]},
            "total_amount": {"type": "number"}
        },
        "required": ["invoice_id", "vendor_name", "purchase_order_number", "total_amount"]
    }
}

response = client.messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=1024,
    tools=[extraction_tool],
    tool_choice={"type": "tool", "name": "submit_invoice_data"}, # Forced tool choice
    messages=[{"role": "user", "content": "Process invoice INV-9901 for AcroCorp total $450.00."}]
)

# Extraction result is available directly as a Python dict in tool_use block input
extracted_data = response.content[0].input
print(extracted_data)
# Output: {'invoice_id': 'INV-9901', 'vendor_name': 'AcroCorp', 'purchase_order_number': None, 'total_amount': 450.0}

```

*Explanation:* Setting `tool_choice` to a specific tool forces Claude to return a structured tool call payload. Allowing `"null"` as a valid schema type for `purchase_order_number` gives the model an explicit path for absent information, preventing fabricated values.

#### 2. Validation-Retry Loop with Context Preservation

```python
def validate_and_retry(client, messages, tools, tool_choice):
    response = client.messages.create(
        model="claude-sonnet-4-20250514",
        max_tokens=1024,
        tools=tools,
        tool_choice=tool_choice,
        messages=messages
    )
    
    tool_block = next(b for b in response.content if b.type == "tool_use")
    data = tool_block.input
    
    # Semantic Validation Logic
    if data.get("total_amount") < 0:
        # Append the assistant's invalid response to message history
        messages.append({"role": "assistant", "content": response.content})
        
        # Pass actionable diagnostic back via tool_result
        messages.append({
            "role": "user",
            "content": [{
                "type": "tool_result",
                "tool_use_id": tool_block.id,
                "is_error": True,
                "content": "Validation Failed: total_amount cannot be negative. Please re-extract."
            }]
        })
        
        # Retry request with updated conversation context
        return validate_and_retry(client, messages, tools, tool_choice)
        
    return data

```

*Explanation:* When semantic validation fails (such as negative monetary amounts), the application appends the assistant's previous attempt and returns a detailed `tool_result` error message so Claude can self-correct.

### 3. Clear & Simple Explanation

Extracting structured data from Claude can be understood through simple analogies:

* **`tool_use` vs. Free-Form Text**: Asking Claude to output plain JSON in text is like asking a human to hand-write a form on a blank sheet of paper; they might miss a bracket or misspell a field key. Using `tool_use` with a JSON schema provides an online digital web form where fields, dropdown types, and numbers are strictly defined.
* **Nullable Fields to Prevent Fabrications**: If a digital form marks "Middle Name" as mandatory and doesn't allow blank submissions, a user without a middle name might enter a fake one. Marking missing fields as nullable gives Claude a valid option to select "None" rather than making up a value.
* **Validation-Retry Loops**: If a student submits a math quiz where line items don't match the total, giving them a blank sheet with "Try again" doesn't help. Telling them specifically, *"Your items sum to $110, but your total says $120"* allows them to fix the exact mistake.
* **Batch API**: Sending real-time requests is like taking express delivery for every single package. The Batch API is like scheduling an overnight freight delivery for non-urgent packages—it takes up to 24 hours but cuts the shipping bill in half.

**Scenario: Automated High-Volume Document Parsing and Verification Pipeline**
An insurance enterprise receives thousands of claim documents daily. The architecture requires extracting structured JSON claims, validating sum calculations, and running nightly batch classification jobs for reporting.

```
                           [Inbound Claim PDF]
                                    │
                                    ▼
                         [Document Text Extractor]
                                    │
                                    ▼
                     [Claude API: Extraction Agent]
                 (tool_choice: forced "submit_claim")

                                    │

                      [Semantic Validation Engine]
                      (Validates sum of line items)
                                    │
                    ┌───────────────┴───────────────┐
                    ▼                               ▼
            [Validation Passed]             [Validation Failed]
                    │                               │
                    ▼                               ▼
            [Store in DB]              [Validation-Retry Loop]
                    │                  (Append tool_result error)
                    ▼                               │
        [Nightly Batch API Jobs] ◄──────────────────┘
     (50% Discount + Caching)

```

1. **Extraction Step**: The extraction pipeline sends OCR text to Claude using `tool_choice: {"type": "tool", "name": "submit_claim"}` to guarantee zero syntax errors.
2. **Schema Defense**: Optional fields like `secondary_policy_number` are marked as `["string", "null"]` to prevent invented policy numbers.
3. **Semantic Verification**: A Python rule engine checks if `itemized_total == sum(line_items)`. If invalid, it appends the invalid output alongside an error description (`is_error: True`), prompting Claude to correct the sum.
4. **Nightly Analytics Batching**: Once extracted, historical claims are sent to the Batch API for sentiment and risk scoring, leveraging prompt caching and the 50% batch discount.

### 5. Key Terms Note Section

### Key Technical Terms

* **`tool_use`**: The Anthropic API mechanism where the model invokes defined function structures rather than generating free-form text responses.
* **JSON Schema**: A formal declaration describing the data types, descriptions, and required structure for tool inputs.
* **`tool_choice`**: An API request parameter controlling whether tool execution is optional (`auto`), mandatory (`any`), or forced for a designated tool.
* **Syntax Error**: Formatting corruption in text strings, such as unclosed braces or unquoted keys, which is eliminated when using `tool_use` schemas.
* **Semantic Error**: Logical inaccuracies within validly formatted JSON payloads, such as incorrect arithmetic sums or mismatched field content.
* **Nullable Field**: A JSON schema property configured with `type: ["string", "null"]` that permits explicit null values to prevent model hallucination on absent data.
* **Validation-Retry Loop**: A resilience pattern that programmatically evaluates model outputs and re-prompts with diagnostic error context upon failure.
* **Batch API**: An asynchronous execution service offering a 50% discount for non-realtime API requests completed within a 24-hour SLA.
* **Prompt Caching**: A feature that stores static prompt prefixes in memory, reducing latency and input token costs on repetitive tasks.

--- **Answer Key & Explanations** ---

1. **B** - **Configure the field type as `["string", "null"]` and update tool instructions to set missing values to `null`.** When schema fields are strictly required without allowing null values, Claude is forced to generate a value even if the information is absent from the source document. Defining fields as nullable gives the model a valid, schema-compliant path for missing data. Option A introduces syntax errors; Option C does not fix schema constraints; Option D does not alter schema validation behavior.
2. **C** - **Append the assistant turn and a `tool_result` block containing the specific math discrepancy error message to the conversation history, then retry.** In a validation-retry loop for semantic errors, Claude needs to inspect its prior tool invocation alongside specific error diagnostics (e.g., math discrepancies) to perform an accurate correction turn. Option A loses prior attempt context; Option B adds latency without correcting input history; Option D hardcodes invalid assumptions without model verification.
3. **C** - **Batch API calls combined with Prompt Caching on the shared system prompt and tool definitions.** The Batch API cuts input/output costs by 50% for non-realtime workloads with a 24-hour SLA. Stacking Prompt Caching further reduces costs on repetitive system prompts and tool schemas. Options A, B, and D use standard real-time endpoints without batch discounts.
4. **C** - **`tool_choice: {"type": "tool", "name": "extract_metadata"}`.** Explicitly specifying a named tool in `tool_choice` forces Claude to execute that exact tool on the turn, preventing plain text output. Option A (`auto`) permits text responses; Option B (`any`) forces a tool call but allows Claude to choose among all provided tools; Option D prevents tool execution entirely.
5. **B** - **It eliminates JSON syntax errors completely, but does not prevent semantic discrepancies or hallucinated values for required fields.** The `tool_use` feature guarantees that output matches the specified JSON Schema structural format, eliminating syntax defects like unclosed braces. However, semantic errors (such as wrong calculations or hallucinated missing data) must still be handled via prompt guidelines, schema field nullability, and validation checks. Options A, C, and D misstate the capabilities of JSON schema enforcement.
