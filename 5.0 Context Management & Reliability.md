# Context Management & Reliability

### 1. Problem statement

Production AI systems processing large-scale context (e.g., insurance policies, legal contracts, multi-agent research tasks) face severe operational risks: progressive summarization silently drops critical fine-print facts (lossy compression), LLMs exhibit lower recall for information in middle context positions ("lost-in-the-middle" effect), multi-agent pipelines propagate unhandled cascading failures, and unanchored facts create hallucinated or unverifiable claims. Without concrete escalation thresholds, structured error propagation, crash recovery state manifests, and explicit claim-source mappings, LLM applications remain unpredictable and unsuitable for enterprise deployment.

### 2. Summary

The [Context Management & Reliability](https://pods.vizuara.ai/courses/claude-certified-architect/context-management-reliability/article) module outlines six foundational technical concepts for architectural reliability:

* **Context Window Management & The Sandwich Pattern**: Progressive summarization degrades accuracy over multiple iterations. To preserve critical details, systems must perform structured fact extraction (schema-bound data with source links) and apply the **Sandwich Pattern**—placing system instructions and critical constraints at both the **beginning** and **end** of the prompt context window to counteract middle-token attention drops.
* **Explicit Escalation Criteria**: AI agents require objective, concrete thresholds (not vague rules like "escalate when complex") to trigger human handoffs. Every escalation must produce a **Structured Handoff Summary** detailing what was attempted, what remains, and relevant context parameters.
* **Structured Error Propagation & Graceful Degradation**: Multi-agent pipelines must avoid silent drops or total pipeline crashes. Agents must return structured payloads differentiating `transient` (retryable) from `permanent` (non-retryable) failures. Multi-step operations leverage **Crash Recovery Manifests** to track state and resume from checkpoints without re-executing completed work.
* **Information Provenance & Temporal Validation**: Every extracted fact requires precise claim-source mapping (document ID, page, paragraph, exact quote, confidence score). Temporal validation logic flags stale extractions or outdated source documents based on age and update frequency.
* **Stratified Sampling for Human Audits**: Random sampling of outputs wastes audit budgets on trivial cases. **Stratified sampling** categorizes outputs into distinct risk tiers (strata) and samples proportionally to error risk (e.g., 1% for simple auto-approvals vs. 50% for new policy types).

## Code Snippets & Explanations

#### 1. The Sandwich Pattern Implementation (`build_context`)

```python
def build_context(system_instructions, extracted_facts, user_query):
    """Place critical info at context boundaries to counteract middle-token attention loss."""
    return f"""
{system_instructions}
CRITICAL RULES (read these carefully):
{extracted_facts['policy_exclusions']}
{extracted_facts['coverage_limits']}

--- Supporting Documentation ---
{extracted_facts['medical_facts']}
{extracted_facts['prior_decisions']}
--- End of Documentation ---

REMINDER - CRITICAL RULES:
{extracted_facts['policy_exclusions']}

User Query:
{user_query}
"""

```

*Explanation:* Placing non-negotiable policy rules at both the top and bottom of the context window ensures high attention weighting regardless of document length, turning model attention mechanics into an asset.

#### 2. Temporal Validity Verification (`check_temporal_validity`)

```python
def check_temporal_validity(claim, now):
    """Flag claims originating from stale or outdated source documents."""
    source_date = claim["source"].get("document_date")
    extraction_date = claim["source"]["extraction_timestamp"]
    warnings = []
    
    # Flag if source document is older than 1 year
    if source_date and (now - source_date).days > 365:
        warnings.append({
            "type": "outdated_source",
            "message": f"Source document is {(now - source_date).days} days old",
            "recommendation": "Verify against current version"
        })
        
    # Flag if extraction is older than quarterly update cycle
    if claim.get("update_frequency") == "quarterly":
        if (now - extraction_date).days > 90:
            warnings.append({
                "type": "stale_extraction",
                "message": "Extraction older than quarterly update cycle",
                "recommendation": "Re-extract from latest version"
            })
    return warnings

```

*Explanation:* Computes source document age and extraction age against update cadences to prevent stale facts from driving decisions.

### 3. Clear & Simple Explanation

Managing long context and agent reliability is like running a hospital medical board:

* **The Sandwich Pattern**: Like reading the most important patient allergies on both the front cover and back cover of a 500-page medical chart so surgeons never miss them.
* **Structured Extraction**: Instead of asking a nurse to "summarize the chart," you ask them to fill out a checklist with exact page numbers for every prescription.
* **Graceful Degradation**: If 1 out of 4 diagnostic tests fails due to a broken machine, the lab sends the 3 completed tests immediately, marks the 4th test as machine-offline, and recommends rescheduling only that 1 test.
* **Crash Recovery Manifest**: A saved game checkpoint. If the power goes out mid-operation, the medical software restarts right at step 4 instead of re-administering step 1.
* **Stratified Sampling**: Auditing 100 patient discharges by picking 5 routine checkups, 35 high-risk surgeries, and 60 unusual drug interactions—spending audit budget where mistakes are most dangerous.

### 4. Real-World Application

**Scenario: Automated Insurance Medical Claims Processing Pipeline**
An enterprise insurance system processes multi-page medical claims, policy exclusion PDFs, and billing histories to adjudicate claims up to $100,000 automatically.

```
                         [Inbound Claim Package]
                                    │
                                    ▼
                      [Structured Extractor Agent]
                 (Extracts Json + Page/Quote Source)
                                    │
                                    ▼
                      [Adjudication Engine (Claude)]
                     (Sandwich Pattern Context Window)
                                    │
              ┌─────────────────────┴─────────────────────┐
              ▼                                           ▼
   [Validation Engine Check]                  [Worker Process Crash]
              │                                           │
      ┌───────┴───────┐                                   ▼
      ▼               ▼                       [Recovery Manifest Read]
[Passed Gate]   [Escalation Trigger]          (Resumes pending files)
      │         (Claim >$100k or Conf <0.70)
      │               │
      ▼               ▼
  [Approved]   [Structured Handoff Summary]
                      │
                      ▼
            [Human Reviewer Queue]
           (Stratified Risk Sample)

```

1. **Extraction**: Documents pass through structured extraction, linking every diagnosis code to exact document IDs, page numbers, and quote strings.
2. **Adjudication**: Prompts format policy exclusions at top and bottom boundaries (Sandwich Pattern) around medical records.
3. **Deterministic Escalation**: Claims exceeding $100,000 or matching confidence under 0.70 automatically output a structured handoff payload to human adjusters.
4. **Crash Recovery**: If extraction workers crash mid-batch, persistent recovery manifests record completed items so processing resumes from the exact failure point.

### 5. Key Terms Note Section

### Key Technical Terms

* **Sandwich Pattern**: A context engineering strategy that places system rules and critical constraints at both the start and end of the context window to counteract middle-token attention drops.
* **Progressive Summarization**: The lossy practice of iteratively summarizing text, which carries a high risk of dropping essential fine-print facts.
* **Structured Extraction**: Direct conversion of unstructured text into JSON schema objects containing precise citation metadata.
* **Lost-in-the-Middle Effect**: The performance drop observed in LLMs when critical information is placed in the middle third of a long context window.
* **Claim-Source Mapping**: Bi-directional citation tracking that connects an extracted fact directly to its source document ID, page, paragraph, and exact quote string.
* **Graceful Degradation**: Architecture design ensuring partial execution results and explicit error payloads are returned rather than causing a complete pipeline crash.
* **Crash Recovery Manifest**: A persistent JSON state file recording completed, in-progress, and pending tasks for resumption without re-execution.
* **Stratified Sampling**: A statistical audit sampling strategy that categorizes data into risk tiers (strata) and samples higher-risk tiers at greater frequencies.
* **Structured Handoff Summary**: A standardized JSON payload passed during human-in-the-loop escalations detailing attempted actions, remaining tasks, and policy context.

* B) A persistent crash recovery manifest recording completed document outputs, in-progress items, and pending item queues.

--- **Answer Key & Explanations** ---

1. **C** - **Implement the Sandwich Pattern by extracting the critical policy exclusion and placing it at both the beginning and the end of the context prompt payload.** The "lost-in-the-middle" effect causes LLMs to pay weaker attention to middle context tokens. Re-stating critical constraints at context boundaries leverages high attention at context entry and exit points. Option A causes lossy compression; Option B does not fix positional attention biases; Option D adds unnecessary API latency and expense.
2. **A** - **Escalate when the customer explicitly mentions keywords "supervisor" or "legal action", or when requested loan modifications exceed $100,000.** Escalation criteria must be concrete, objective, and testable. Options B and C rely on subjective or unreliable estimations; Option D uses token count rather than business risk thresholds.
3. **D** - **Output a structured JSON response containing the 8 completed results along with a `failed` array categorizing the 503 error as `transient` (retryable) and the language error as `permanent`.** Graceful degradation requires full transparency regarding partial successes and explicit error classification so downstream agents can handle retries appropriately. Option A represents silent failure; Option B causes complete system breakage; Option C wastes resources retrying permanent errors.
4. **C** - **Implement stratified sampling that allocates review capacity proportionally to error risk tiers (e.g., higher sample rates for high-value claims and edge cases).** Stratified sampling distributes review capacity based on error risk rather than volume, ensuring audit budgets focus on complex or high-value cases where errors are most costly. Option A wastes capacity on simple cases; Options B and D fail to cover high-risk outputs systematically.
5. **B** - **A persistent crash recovery manifest recording completed document outputs, in-progress items, and pending item queues.** A crash recovery manifest logs checkpoints and status per task item, allowing a restarted process to pick up exactly where it failed without wasting tokens on completed work. Option A caches prompt prefixes but does not track item completion state; Options C and D do not provide state recovery mechanics.
