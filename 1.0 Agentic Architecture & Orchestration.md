### Agentic Architecture & Orchestration

### 1. Problem statement

Designing enterprise-grade agentic systems requires moving beyond rigid if/else code branches without compromising execution safety, regulatory compliance, or context window efficiency. Traditional approaches either over-constrain the model with hardcoded logic or rely solely on probabilistic prompts that fail to enforce strict business rules, leading to runaway loops, high token costs, and compliance risks.

### 2. Summary

The [Agentic Architecture & Orchestration](https://pods.vizuara.ai/courses/claude-certified-architect/agentic-architecture/article) lesson outlines seven foundational concepts required for building production agentic systems on Claude:

1. **The Agentic Loop Lifecycle**: Driven directly by the model's `stop_reason` (`tool_use` to call functions or `end_turn` to complete execution).
2. **Multi-Agent Coordinator Patterns**: Hub-and-spoke models where a central coordinator delegates work to specialized subagents operating with **isolated context windows**.
3. **Subagent Invocation via Task Tool**: Spawning subagents through `AgentDefinition` configurations using the `Task` tool (`allowedTools: ["Task"]`).
4. **Multi-Step Workflows & Compliance**: Using programmatic enforcement (code gates) instead of system prompts for non-negotiable business rules (e.g., identity verification before money transfers).
5. **Agent SDK Hooks**: Intercepting tools via `PreToolUse` (blocking policy violations like refunds > $500) and `PostToolUse` (normalizing tool output formats like Unix timestamps to ISO 8601).
6. **Task Decomposition Strategies**: Choosing fixed sequential pipelines (prompt chaining) for deterministic workflows versus dynamic adaptive decomposition for open-ended exploration.
7. **Session Management & Recovery**: Preserving state across sessions with `--resume` (informing agents of external file changes) or branching parallel exploration paths with `fork_session`.

#### Core Architectural Patterns Comparison

| Architectural Pattern / Feature | Primary Use Case | Key Advantage | Exam Best Practice / Guidance |
| --- | --- | --- | --- |
| **Fixed Sequential Pipeline** | Known, step-by-step processes (e.g., loan applications) | Highly predictable and easily auditable | Use when task steps do not vary dynamically. |
| **Dynamic Adaptive Decomposition** | Open-ended tasks (e.g., software bug investigation) | High flexibility based on step discoveries | Pair per-file analysis with a cross-file integration pass. |
| **Prompt-Based Guidance** | Soft rules (e.g., brand tone, asking questions) | Easy to implement in system prompt | Never rely on this for strict regulatory or safety rules. |
| **Programmatic Hooks / Gates** | Strict business caps, identity checks, data formatting | 100% deterministic compliance | Mandatory for financial limits, security, and schema normalization. |

## Code Snippets & Explanations

#### Minimal Agentic Loop Implementation

```python
import anthropic

client = anthropic.Anthropic()
tools = [{
    "name": "lookup_order",
    "description": "Look up order by ID",
    "input_schema": {
        "type": "object",
        "properties": {"order_id": {"type": "string"}}
    }
}]

messages = [{"role": "user", "content": "What is the status of order ORD-1234?"}]

while True:
    response = client.messages.create(
        model="claude-sonnet-4-20250514",
        max_tokens=1024,
        tools=tools,
        messages=messages
    )
    # The model decides what happens next via stop_reason
    if response.stop_reason == "end_turn":
        print(response.content[0].text)
        break
    if response.stop_reason == "tool_use":
        tool_block = next(b for b in response.content if b.type == "tool_use")
        result = execute_tool(tool_block.name, tool_block.input)
        
        # Append assistant response AND tool result to history
        messages.append({"role": "assistant", "content": response.content})
        messages.append({
            "role": "user",
            "content": [{
                "type": "tool_result",
                "tool_use_id": tool_block.id,
                "content": result
            }]
        })

```

*Explanation:* The control flow relies entirely on `response.stop_reason`. When set to `"tool_use"`, the application executes the requested tool, appends the assistant message and user `tool_result` to history, and resumes the loop until `stop_reason == "end_turn"`.

#### Subagent Instantiation with Task Tool

```python
from claude_agent_sdk import AgentDefinition

research_agent = AgentDefinition(
    model="claude-sonnet-4-20250514",
    system_prompt="You are a research specialist. Search for and summarize information.",
    tools=["web_search", "read_document"],
    max_tokens=4096
)

# Explicit context passing - subagent receives ONLY this prompt payload
task_result = coordinator.invoke_tool("Task", {
    "agent": research_agent,
    "prompt": f"""Research the following customer issue:
    Customer ID: {customer_id}
    Order ID: {order_id}
    Complaint: {complaint_text}
    Find the relevant return policy and precedent cases."""
})

```

*Explanation:* Demonstrates how a central coordinator agent uses the `Task` tool to invoke a child subagent with an isolated context window, passing only necessary context explicitly.

#### Programmatic Compliance via Hooks

```python
from datetime import datetime, timezone

def normalize_timestamps(tool_name, tool_result):
    """PostToolUse hook: convert Unix timestamps to ISO 8601."""
    if "timestamp" in tool_result:
        unix_ts = tool_result["timestamp"]
        dt = datetime.fromtimestamp(unix_ts, tz=timezone.utc)
        tool_result["timestamp"] = dt.isoformat()
    return tool_result

def enforce_refund_policy(tool_name, tool_input):
    """PreToolUse hook: block refunds over $500."""
    if tool_name == "process_refund":
        amount = tool_input.get("amount", 0)
        if amount > 500:
            return {
                "blocked": True,
                "reason": f"Refund of ${amount} exceeds $500 limit. Manager approval required."
            }
    return {"blocked": False}

```

*Explanation:* `PostToolUse` normalizes output payloads (e.g., converting Unix epoch integers into readable ISO 8601 timestamps), while `PreToolUse` deterministically intercepts and blocks non-compliant action requests before execution.

### 3. Clear & Simple Explanation

Think of an agentic system like a professional restaurant kitchen:

* **Agentic Loop**: The chef tastes the sauce and decides whether it needs more salt (another tool execution step) or if it's ready to be served (`end_turn`).
* **Hub-and-Spoke Subagents**: The head chef delegates specific tasks to station chefs (e.g., pastry, grill). The station chefs don't need to know the entire dining room order history; they only receive the specific ticket for their dish (**isolated context**).
* **Hooks**: Programmatic safety inspectors at each station. `PreToolUse` stops spoiled food from being cooked (blocks policy violations), and `PostToolUse` cleans up the plate presentation before sending it out (data normalization).
* **Session Recovery & Forking**: Saving your game before taking on a hard level (`--resume`) or trying two different tactical paths simultaneously in duplicate save files (`fork_session`).

### 4. Real-World Application

**Scenario: Automated Financial Refund & Customer Escalation System**
An e-commerce platform processes user order refund requests while strictly enforcing regulatory identity verification and manager spending caps.

**Architectural Workflow Diagram:**

```
[Inbound Customer Request]
            │
            ▼
 [Coordinator Agent (Hub)] ───(PreToolUse: Identity Verification Gate)───► [Auth DB]
            │
            ├──────────────────────────┬──────────────────────────┐
            ▼                          ▼                          ▼
   [Task: Order Lookup]       [Task: Policy Review]    [Task: Risk Analysis]
   (Subagent 1 - Isolated)    (Subagent 2 - Isolated)  (Subagent 3 - Isolated)
            │                          │                          │
            └──────────────────────────┴──────────────────────────┘
                                       │
                                       ▼
                     [PostToolUse: Timestamp Normalizer]
                                       │
                                       ▼
                   [PreToolUse Hook: Refund Cap ($500 Cap)]
                                       │
                      ┌────────────────┴────────────────┐
            [Amount <= $500]                    [Amount > $500]
                      │                                 │
                      ▼                                 ▼
           [Execute Refund Tool]           [Structured Handoff Payload]
                                                        │
                                                        ▼
                                            [Human Support Desk]

```

1. **Request Reception**: User requests a refund for duplicate billing.
2. **Identity Verification**: The Coordinator Agent triggers a mandatory programmatic gate verifying user credentials.
3. **Subagent Orchestration**: Coordinator uses the `Task` tool to spin up isolated research and policy subagents in parallel.
4. **Data Normalization**: `PostToolUse` transforms database timestamps into standard ISO strings before passing data back to Claude.
5. **Deterministic Policy Check**: When `process_refund` is invoked, `PreToolUse` evaluates the refund value. If under $500, execution proceeds; if over $500, execution is blocked and packaged into a structured handoff payload for human review.

### 5. Key Terms Note Section

Technical concepts and keywords sourced directly from the [Vizuara AI Pods](https://pods.vizuara.ai/courses/claude-certified-architect/agentic-architecture/article) curriculum are defined below.

### Key Technical Terms

* **Agentic Loop**: An iterative execution cycle where the LLM inspects previous outputs and dynamically determines the next tool call or loop termination.
* **`stop_reason`**: An official Claude API response field (`tool_use` or `end_turn`) used as the primary programmatic control flow mechanism.
* **Hub-and-Spoke Architecture**: A multi-agent coordinator pattern where a single central hub delegates focused subtasks to independent subagent spokes.
* **Isolated Context**: The strategy of providing subagents with only the prompt and data needed for their subtask, omitting the coordinator's complete historical transcript.
* **`Task` Tool**: The Claude Agent SDK tool enabling a master agent to instantiate and run child subagents.
* **`AgentDefinition`**: A configuration object specifying the model, system instructions, tools, and token limits for a specific subagent.
* **Programmatic Enforcement**: Using deterministic code gates and hooks rather than probabilistic prompt instructions to guarantee compliance rules.
* **`PreToolUse` Hook**: A code hook executed prior to tool execution to validate input parameters or block unauthorized actions.
* **`PostToolUse` Hook**: A code hook executed after tool execution to transform or normalize tool outputs before returning them to the model context.
* **Prompt Chaining**: A fixed sequential pipeline strategy where step outputs pass directly into subsequent pre-planned steps.
* **Dynamic Adaptive Decomposition**: A runtime strategy where an agent continuously analyzes findings to construct and adjust its own execution plan.
* **`fork_session`**: A branching tool that creates an independent copy of an agent's current state for parallel exploratory testing.
* **Structured Handoff Protocol**: A standardized schema summarizing customer info, root cause, executed steps, and recommendations when transferring tasks to human operators.

5. In a minimal Anthropic API python implementation of an agentic loop, which control logic is considered an anti-pattern for determining whether the loop should terminate?

* A) Checking if `response.stop_reason == "end_turn"`.
* B) Checking if `response.stop_reason == "tool_use"`.
* C) Searching for natural language strings such as `"I am done"` or `"Finished"` in `response.content[0].text`.
* D) Appending `tool_result` content to the message list before sending the next API request.

---

--- **Answer Key & Explanations** ---

1. **B** - **Implement isolated context windows by passing only required task context within the subagent `Task` invocation prompt.** Subagents in Claude's hub-and-spoke model operate best with isolated context windows. Passing full historical transcripts from the coordinator wastes context window space and increases token costs. Option A exacerbates token usage; Option C still incurs extra processing overhead; Option D removes necessary specialization.
2. **C** - **Implement a deterministic `PreToolUse` hook in code that programmatically evaluates tool parameters and blocks any `process_refund` call over $500.** Hard compliance bounds must be programmatically enforced in code using gates or hooks, as system prompts are probabilistic and can be bypassed. Options A and B rely on prompt guidance; Option D fails to deterministically block the underlying tool execution call.
3. **D** - **The agent's session state contained stale tool results from prior file state; fix it by explicitly passing file delta notifications to the resumed session.** Resuming a session preserves historical context and tool output history. If external workspace files change, the agent's context becomes stale unless explicitly updated with file modification details upon resuming. Options A, B, and C address unrelated concepts.
4. **A** - **A `PostToolUse` hook that intercepts and normalizes the `tool_result` payload before returning it to the conversation history.** `PostToolUse` hooks execute immediately after a tool returns its output, making them the correct mechanism for data normalization before the model processes the context. Option B blocks valid operations unnecessarily; Option C forces unnecessary probabilistic work onto the model; Option D escalates unnecessarily to humans.
5. **C** - **Searching for natural language strings such as `"I am done"` or `"Finished"` in `response.content[0].text`.** Parsing natural language text for loop termination is a critical anti-pattern because language is inherently ambiguous. System control flow should always rely explicitly on `response.stop_reason` (`tool_use` or `end_turn`). Options A, B, and D reflect proper standard practices for agentic loop implementation.
